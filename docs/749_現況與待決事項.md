## §1 749 和 723 的差別
- 749 沒有「類型」欄位、沒有分攤表、供應商列表、交際費／出差子表格，也沒有從請購／庶務帶入資料。
- 欄位代碼改名：員工姓名 → `申請人`、申請單位 → `申請人部門`；子表格 日期_交通費請款單 → `憑證日期`、金額_交通費請款單 → `金額`、起訖點_交通費請款單 → `起訖點`、費用歸屬_交通費請款單 → `費用歸屬`；`理由` 從子表格搬到主表。
- 749 新增：`費用所屬人`、`費用所屬人部門`、`是否有紙本憑證`；子表格 `憑證種類`、`發票號碼`、`賣方統編`、`格式`、`稅額`、`備註`。子表格**沒有總金額欄**。
- 流程管理：「點擊流程開始」後的狀態是 `草稿（未送出）`（rev 1798 起，與 723 等其他 App 一致；之前叫「申請開始」）。
- 版面（rev 1798）：申請人部門、費用所屬人部門移進「簽核流程」群組（預設收合；兩欄本來就鎖住、依人員帶入）；子表格「交通費請款單」欄位順序與標籤見 `form_snapshots/749_rev1798_traffic_table.json`（kintone MCP 讀出，config 的 `TRAFFIC_TABLE_LAYOUT` 與它一致，測試會比對）。
- 版面空白欄位（rev 1795 起）：`Space_Noti_2`（付款說明）、`Space_Noti_3`（受款人說明）、`apply_button`（同申請人按鈕）、`Space_Expected_Pay_Date`（預計付款日說明）；另有未使用的 `Space_Expected_Pay_Date_0`。`Space_Noti_1` 已從表單移除，程式找不到時直接略過（config 的 `SPACES.NOTI_1` 目前沒有作用）。

## §2 已拍板的設計
1. **簽核人員依費用所屬人／費用所屬人部門排**；會計單位、權限開放人員、會計單位承辦人也依費用所屬人部門查會計對應主檔（`APPS.ACCOUNTING_MAP`）。**會計單位只有這一個來源**（2026-10-22）：改費用歸屬不會動會計單位（723 依費用歸屬據點與機場／海運特殊代碼判斷的程式已刪）。
2. **部門只依人員帶入、一律鎖住**（2026-10-22）：
   - 費用所屬人部門依費用所屬人、申請人部門依申請人（`申請人部門帶入_20261022.js`），兩個部門欄位所有人（含管理員）都不能手改。
   - 改人員 → 查他的所屬單位：只有一個直接帶入；兩個以上跳視窗選（主要單位預選）。原部門也是這個人的單位才給「取消（保留原部門）」，否則一定要選。兩個視窗同時要開時排隊，不會互相蓋掉。
   - 新增畫面（create.show）：部門是該人的單位就不動；空白或不是（例如複製別人的單）就重新帶入。清空人員 → 部門跟著清空。
   - 費用所屬人部門帶入後重排簽核人員、重算公司名稱。部門和費用所屬人不一致時不再跳「請選取費用所屬人正確所在的部門」，改由重新帶入處理。
3. **排人沿用 723「交通費」的完整鏈**：簽核流程主檔有值的課長／次長／部長全部排上，費用所屬人本人那一層與以下依職稱清掉；**沒有職稱就不清，全部排上**（2026-10-22）。723 給請購／交際費用的「往上一階只留一位」、「唯一簽核人放主管3」已刪除。手動設定簽核流程保留。
4. **申請人／受款人**：只有管理員可改。費用所屬人開放所有人改。申請人部門、費用所屬人部門見 2.
5. **公司名稱**：依費用所屬人部門代碼是否以「聯海」開頭推導，鎖住。
6. **受款人**：按鈕「同申請人」，填申請人的「員工代碼 中文姓名」（723 是 `員工姓名`，749 對應 `申請人`；2026-10-22 由「同費用所屬人」改回）。新增時受款人空白就自動帶入申請人；已有值不覆蓋，編輯畫面不自動帶。
7. **稅額自動算（2026-10-22 改）**：金額含稅，稅額＝金額 ÷ 1.05 × 0.05 四捨五入到個位數，**每一列都算**、稅額鎖住，存檔時再算一次為準。
8. **預計付款日**：一律套用（723 只給請購、交際費）。
9. **PDF 下載按鈕**掛在詳細頁頁首選單空白處（749 沒有 723 的 `Purchase_button` 空白欄位）。
10. **交通費明細規則**（`交通費明細規則_20261022.js`，2026-10-22）：
    - 交通工具＝高鐵 → 賣方統編 `00000000`、格式 `22`，兩欄鎖住（`TRAFFIC_RULES`）。
    - 憑證種類＝高鐵票／發票 → 發票號碼開放填寫，**存檔必填**、本單不可重複；其他種類清空並鎖住。存檔前重算「發票號碼記錄」，跨單重複照舊查記錄欄位（不迴圈讀表格）；重複時錯誤視窗逐一列出撞到的號碼與對方的交通費請款單號。
    - 有任何一列是計程車 → 是否有紙本憑證自動選「是」（存檔時強制）、理由必填（標籤加紅色 *，存檔驗證擋）。
    - 開畫面只加鎖、不解鎖（不蓋掉帳號權限設定的鎖定）；變更事件才會解鎖。
11. **掛帳單位限部內**（`費用歸屬部門限制_20261022.js`，2026-10-22）：
    - 每列費用歸屬的「所屬部門」（費用歸屬主檔 `REF_FIELDS.COST_CENTER.DEPT`）必須包含費用所屬人部門沿組織樹往上爬到的部；所有列找不到共同的部另報「不能跨部門」。組織樹快取在 localStorage 6 小時（做法同 723 交際費）。
    - **共用代碼**：同一代碼在主檔建多筆、各屬不同部門時（例如總公司代碼 AJ30 分屬營業戰略部、安全品質推動部、總務部），所屬部門全部收進來，任一個部符合就算部內。
    - 申請人在 `COST_SCOPE.EXEMPT_GROUP`（「費用歸屬不限部門」）群組 → 不檢查；create.show／edit.show 先查好存在模組變數。群組 API 失敗當作不在名單（寧可多擋）。
    - 同一批人**新增時自動勾「手動設定簽核流程」**，簽核人員自選。
12. **手動設定簽核流程時不重排**（原 §3.3）：改費用所屬人／部門只帶會計單位承辦人與權限開放人員，不蓋掉自選的簽核人員；排人查詢回來前才勾手動也不蓋。

13. **手機版範圍**（2026-10-22）：新增／編輯／詳細畫面的表單行為都上手機版（部門帶入、簽核人員與會計單位、明細規則、存檔驗證、預計付款日、受款人、自動推進、作廢確認、儲存中提示）。
    列表頁工具（批次下載／PDF／SAP 轉檔）、列印頁、附件預覽、費用歸屬中文名稱提示、欄寬調整只在桌面版。**帳號權限設定也只在桌面版**（見 §3.11）。

11. **帳號權限設定在手機版不生效**：模組靠桌面版 DOM 調整欄位，本身也註明「行動版不套用」，所以手機版沒有依角色／關卡的欄位顯示、鎖定、必填（例如傳票編號、傳票日期）。
    要不要手機版也套用？要的話需改寫成 `kintone.mobile.app.record` 的 API，必填標示另做。若暫不做，可考慮在 kintone 權限設定限制手機版存取。
