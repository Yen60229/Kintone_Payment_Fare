## §1 749 和 723 的差別
- 749 沒有「類型」欄位、沒有分攤表、供應商列表、交際費／出差子表格，也沒有從請購／庶務帶入資料。
- 欄位代碼改名：員工姓名 → `申請人`、申請單位 → `申請人部門`；子表格 日期_交通費請款單 → `憑證日期`、金額_交通費請款單 → `金額`、起訖點_交通費請款單 → `起訖點`、費用歸屬_交通費請款單 → `費用歸屬`；`理由` 從子表格搬到主表。
- 749 新增：`費用所屬人`、`費用所屬人部門`、`是否有紙本憑證`；子表格 `憑證種類`、`發票號碼`、`賣方統編`、`格式`、`稅額`、`備註`。子表格**沒有總金額欄**。
- 流程管理：「點擊流程開始」後的狀態是 `申請開始`（723 是「草稿（未送出）」）。
- 版面空白欄位（rev 1795）：`Space_Noti_2`（付款說明）、`Space_Noti_3`（受款人說明）、`apply_button`（同申請人按鈕）、`Space_Expected_Pay_Date`（預計付款日說明）；另有未使用的 `Space_Expected_Pay_Date_0`。`Space_Noti_1` 已從表單移除，程式找不到時直接略過（config 的 `SPACES.NOTI_1` 目前沒有作用）。

## §2 已拍板的設計
1. **簽核人員依費用所屬人／費用所屬人部門排**；會計單位、權限開放人員、會計單位承辦人也依費用所屬人部門查會計對應主檔（`APPS.ACCOUNTING_MAP`）。
2. **費用所屬人改了 → 自動帶入費用所屬人部門**：只有一個單位直接帶入；兩個以上跳視窗選（主要單位預選，取消保留原部門）；帶入後重排簽核人員、重算公司名稱。所有人都適用。新增畫面若費用所屬人有預設值、但部門空白，也走同一套流程補上部門。
3. **排人沿用 723「交通費」的完整鏈**：簽核流程主檔有值的課長／次長／部長全部排上，費用所屬人本人那一層與以下依職稱清掉。723 給請購／交際費用的「往上一階只留一位」、「唯一簽核人放主管3」已刪除。手動設定簽核流程保留。
4. **申請人／申請人部門／受款人**：只有管理員可改。費用所屬人、費用所屬人部門開放所有人改。
5. **公司名稱**：依費用所屬人部門代碼是否以「聯海」開頭推導，鎖住。
6. **受款人**：按鈕「同申請人」，填申請人的「員工代碼 中文姓名」（723 是 `員工姓名`，749 對應 `申請人`；2026-10-22 由「同費用所屬人」改回）。新增時受款人空白就自動帶入申請人；已有值不覆蓋，編輯畫面不自動帶。
7. **稅額自動算（2026-10-22 改）**：金額含稅，稅額＝金額 ÷ 1.05 × 0.05 四捨五入到個位數，**每一列都算**、稅額鎖住，存檔時再算一次為準。
8. **預計付款日**：一律套用（723 只給請購、交際費）。
9. **PDF 下載按鈕**掛在詳細頁頁首選單空白處（749 沒有 723 的 `Purchase_button` 空白欄位）。
10. **交通費明細規則**（`交通費明細規則_20261022.js`，2026-10-22）：
    - 交通工具＝高鐵 → 賣方統編 `00000000`、格式 `22`，兩欄鎖住（`TRAFFIC_RULES`）。
    - 憑證種類＝高鐵票／發票 → 發票號碼開放填寫，**存檔必填**、本單不可重複；其他種類清空並鎖住。存檔前重算「發票號碼記錄」，跨單重複照舊查記錄欄位（不迴圈讀表格）；重複時錯誤視窗逐一列出撞到的號碼與對方的交通費請款單號。
    - 有任何一列是計程車 → 是否有紙本憑證自動選「是」（存檔時強制）、理由必填（標籤加紅色 *，存檔驗證擋）。
    - 開畫面只加鎖、不解鎖（不蓋掉帳號權限設定的鎖定）；變更事件才會解鎖。
11. **掛帳單位限部內**（`費用歸屬部門限制_20261022.js`，2026-10-22）：
    - 每列費用歸屬的「所屬部門」（費用歸屬主檔 `REF_FIELDS.COST_CENTER.DEPT`）必須等於費用所屬人部門沿組織樹往上爬到的部；分屬兩個以上部門另報「不能跨部門」。組織樹快取在 localStorage 6 小時（做法同 723 交際費）。
    - 申請人在 `COST_SCOPE.EXEMPT_GROUP`（「費用歸屬不限部門」）群組 → 不檢查；create.show／edit.show 先查好存在模組變數。群組 API 失敗當作不在名單（寧可多擋）。
    - 同一批人**新增時自動勾「手動設定簽核流程」**，簽核人員自選。
12. **手動設定簽核流程時不重排**（原 §3.3）：改費用所屬人／部門只帶會計單位承辦人與權限開放人員，不蓋掉自選的簽核人員；排人查詢回來前才勾手動也不蓋。

## §3 待使用者決定
1. **稅額**：目前每一列都算 5%（照 2026-10-22 指示）。沒有發票的憑證（收據、計程車無發票）是否應為 0？`格式`、`賣方統編` 非高鐵時要不要必填或檢查格式？
2. **`憑證種類` 要不要必填**（723 的交通費「註記」是必填）？
3. **發票號碼必填**：高鐵票／發票目前存檔時必填，若有「先送單、號碼後補」的情境要放寬。
3a. **待在 kintone 上確認（本次沒有 kintone MCP 可查 749／661 欄位）**：
   - 選項值是否一字不差：交通工具「高鐵」「計程車」、憑證種類「高鐵票」「發票」、是否有紙本憑證「是」（都收在 `OPTIONS`）。
   - `格式` 若是下拉選單，要有「22」這個選項；`稅額` 是數值欄位。
   - 費用歸屬主檔是否有 `所屬部門`（ORGANIZATION_SELECT）且使用中的代碼都有填——**欄位不存在時主檔整個載入失敗，存檔會被擋**。
   - 「理由」標籤文字開頭是「理由」（紅色 * 靠標籤文字找）。
   - kintone 群組「費用歸屬不限部門」已建立並放入人員。
3b. **排除名單的人走手動流程**：流程管理 rev 1795 手動流程送會計只認 NX 承辦人（見 8.），聯海的排除名單成員會卡住。
4. **SAP 轉檔（`APPS.SAP_MAPPING`）**：對應設定的語法還是 723 的欄位（如 `{{供應商列表.費用歸屬}}`），749 匯出會是空值。要為 749 另建一套對應（例如 `{{交通費請款單.費用歸屬}}`）嗎？
5. **帳號權限設定（`APPS.PERMISSION`）**：需要為 749 建規則（`APP_ID = 749`）；沒有規則時欄位維持 kintone 預設。
6. ~~**預計付款日說明文字**~~：已完成（2026-10-22，rev 1795 已加 `Space_Expected_Pay_Date`）。
7. **費用歸屬錯誤訊息**沿用「不屬於 YYYY 年最新分攤表」，749 沒有分攤表，要不要改措辭？
8. **749 流程管理（rev 1795，與 1791 相同）本身的問題**（`npm run check:process` 找到，未改流程檔）：
   - 「申請單位主管3確認中」「申請單位次長1確認中」的「提交單位會計入帳」只看會計單位，沒排除「有部長」「有次長」→ 有部長或次長時同時出現兩顆送出按鈕。
   - 手動流程在「申請單位主管3確認中」送會計的條件只認承辦人屬於 `NX臺灣國際物流`，承辦人在聯海通運時沒有送出按鈕。
   - 「申請單位次長確認中 → 提交單位會計入帳」條件要求次長 1 人，但這一關只有次長 2 人才會進來 → 6 條永遠按不到。
   - 「入帳完成」條件是 `傳票日期 = THIS_YEAR()`，傳票日期填去年（例如跨年入帳）時沒有入帳完成按鈕。
   - 修好流程後重新匯出、更新 `tests/process_checks.test.cjs` 的已知問題清單。
